Aktualny kontrakt jest taki: w kodzie endpoint ma ścieżkę /api/v1/devices/{deviceId}/info, nie device/{id}/info bez prefiksu /api/v1 (src/main/java/pl/rea/api/device/DeviceQueryController.java:14-38).

  Endpoint

  - GET /api/v1/devices/{deviceId}/info
  - Wymaga uwierzytelnienia JWT (@PreAuthorize("isAuthenticated()")).
  - Zwraca jeden obiekt DeviceInfoResponseDto bez wrappera listy (src/main/java/pl/rea/api/device/DeviceQueryController.java:32-38, src/main/java/pl/rea/api/device/dto/DeviceInfoResponseDto.java:6-36).

  Błędy

  - 401 Unauthorized jeśli nie ma poprawnego użytkownika.
  - 404 Not Found jeśli urządzenie nie należy do zalogowanego użytkownika albo nie istnieje (src/main/java/pl/rea/api/device/DeviceQueryService.java:104-109).

  Pola odpowiedzi

  - id Long - wewnętrzne ID urządzenia.
  - businessId String - biznesowy identyfikator urządzenia.
  - displayName String - nazwa wyświetlana.
  - traccarDeviceId Long | null - ID urządzenia w Traccar.
  - connectivityStatus String - status łączności:
      - jeśli istnieje snapshot traccar_device, bierze dokładnie traccar_device.status,
      - jeśli snapshotu nie ma i traccarDeviceId == null, zwraca NOT_CONNECTED,
      - jeśli snapshotu nie ma, ale traccarDeviceId != null, zwraca SYNC_PENDING (src/main/java/pl/rea/api/device/DeviceQueryService.java:140-149).
  - sensorLive Boolean - true tylko gdy traccar_device.status równa się online bez względu na wielkość liter; w pozostałych przypadkach false (src/main/java/pl/rea/api/device/DeviceQueryService.java:142-148).
  - locationStatus String - wyliczany:
      - NO_POSITION, gdy brak pozycji,
      - LIVE, gdy jest pozycja i sensorLive == true,
      - STALE, gdy jest pozycja, ale sensorLive == false (src/main/java/pl/rea/api/device/DeviceQueryService.java:157-161).
  - locationLive Boolean - true tylko gdy sensorLive == true i istnieje lastPosition; inaczej false (src/main/java/pl/rea/api/device/DeviceQueryService.java:157-161).

  Live tracking

  - liveTrackingEnabled Boolean | null
  - Jest wyciągane z traccar_device.attributesJson.
  - Backend sprawdza kolejno klucze: liveTracking, live_tracking, live, realtime, realTime.
  - Obsługiwane wartości:
      - boolean true/false,
      - liczby 0/1,
      - teksty true/false/yes/no/on/off.
  - Jeśli JSON jest pusty, niepoprawny albo brak dopasowania, pole będzie null (src/main/java/pl/rea/api/device/DeviceQueryService.java:131-155, src/main/java/pl/rea/api/device/DeviceQueryService.java:269-351).

  Ważne dla PWA

  - To jest endpoint do odświeżenia całego widoku szczegółów urządzenia.
  - Najbezpieczniej traktować wszystkie pola poza id, businessId, displayName jako opcjonalne.
  - assignedPet i lastPosition mogą być null.
  - connectivityStatus i locationStatus są stringami, ale ich bieżące wartości w implementacji są opisane wyżej.
  - Część telemetrii może pochodzić z fallbacku device_attributes, więc UI nie powinien zakładać, że źródłem zawsze jest snapshot Traccar.
